## Findings and resolutions

### Stage 1 (blocking)

1. **AC-03 guard had no behavioral test.** The only AC-03 test checked the engine's exported keys +
   frozen-ness, never that a stray input is actually ignored — T3's own checklist and ADR-0002
   ("provable ... by the dispatched-`MessageEvent` test") required more.
   **Resolution: Fixed.** Added a source-level test (`test/logic/timer-engine.test.js`, "engine
   surface (AC-03)") that scans every `.js` file under `src/` and asserts none register a `message`
   listener / `onmessage` / `postMessage` / `BroadcastChannel`. A DOM-dispatched `MessageEvent` test
   was not used — this repo has no DOM/jsdom test environment, and adding one for a single assertion
   was judged not worth the new dependency. ADR-0002 was amended (2026-09-27 note) to describe this
   static check instead of the runtime one it originally proposed.

2. **AC-02 (Pause disabled when not running) had no automated test.** Correct in `src/ui/index.js`
   but unverified.
   **Resolution: Fixed.** Extracted a pure `controlStates(snapshot)` helper into `src/logic/index.js`
   (`{startDisabled, pauseDisabled}`), wired `src/ui/index.js`'s `render()` to use it, and added 4
   unit tests covering idle/running/paused/just-completed states.

3. **`sad.md` §6 had no sequence flow for US-03/US-05 or for AC-03/04/06/07/08** — only 2 of the
   spec's user stories were diagrammed, though the code and tasks did cover the rest.
   **Resolution: Fixed.** Added Flow 3 (initial mount → AC-08, plus foreground phase completion
   covering AC-04/AC-07) and Flow 4 (Reset from any state → AC-06), and a short prose note explaining
   why AC-03 has no diagram (nothing to sequence — the guard is structural, not a runtime branch).
   All 6 `sad.md` Mermaid diagrams (2 original + 2 new + C4 Context/Container) validated with `mmdc`.

4. **`src/logic/index.js` exports more than ADR-0002's literal "no other symbol" wording allowed**
   (`PHASES`, `formatDuration`, and the new `controlStates` — none of which can reach engine state).
   **Resolution: Fixed.** Amended ADR-0002 (2026-09-27 note) and `sad.md` §5 to the precise intent:
   "exactly one *stateful* factory; other exports must be frozen constants or pure functions with no
   access to engine state" — matching T1's own original wording.

### Stage 2 (quality) — user chose "fix all of them now"

5. **Backward clock jump wasn't clamped on the upper end** (`src/logic/index.js`) — an OS clock
   moving backward mid-phase could show more than the phase's full duration.
   **Fixed.** Added `clampRemaining(phase, ms)` (clamps to `[0, full duration]`), applied in `pause()`
   and `getSnapshot()`; 2 new tests.

6. **`aria-live="polite"` was on the per-second countdown instead of the phase label** — the element
   that changes every render tick was the live one; the element that actually matters for a screen
   reader (the phase switching at completion, AC-07) wasn't.
   **Fixed.** Moved `aria-live="polite"` to the phase label; countdown now has `role="timer"`
   (implicitly `aria-live="off"`). `render()` also now only writes `textContent` when the string
   actually changed, to avoid announcement noise.

7. **Keyboard focus stranded on a disabled button after Start/Pause.**
   **Fixed.** Added `refocusIfStranded()` in `src/ui/index.js`: after a click handler disables the
   button that had focus, focus moves to the now-enabled sibling control.

8. **`main.js` / `sad.md` §5 / T5 disagreed on who instantiates the engine, and T5 misquoted
   CLAUDE.md** (`sad.md` documented `main.js` instantiating the engine and injecting it into
   `ui.mount`; the code had `ui/index.js` create it internally; T5 labeled a paraphrase "verbatim").
   **Fixed by changing the code to match the documented design** (the design was the more
   encapsulated one): `main.js` now does `mount(root, createTimerEngine())`; `src/ui/index.js`'s
   `mount(root, engine)` takes the engine as a parameter. T5's misquote corrected to CLAUDE.md's
   actual text ("wires `logic` and `ui` together"), with the concrete detail added as a separate,
   correctly-labeled line from `sad.md` §5.

9. **Task files' frontmatter said `status: "todo"` with unchecked checklists while `tracker.md` said
   `done`.**
   **Fixed.** All 7 task files' `status` flipped to `"done"`; every checklist/DoD checkbox that is
   now genuinely verified is ticked.

10. **T7's README didn't document the GitHub Pages deploy mechanics** (only a bare "Live:" link).
    **Fixed.** Added 3 lines to `README.md` explaining Pages serves the committed root `index.html`
    directly off `master` with no build step on the Pages side, so `npm run build` must run and be
    committed locally before pushing.

11. **The AC-06 reset test only covered the trivial idle-phase case**, not running/paused, and never
    asserted `phase`/`focusCount` in those states.
    **Fixed.** Added 2 tests: reset while running and reset while paused, both mid-cycle (short
    break, `focusCount === 1`), both asserting `phase`, `focusCount`, `running`, and `remainingMs`.

## Known limitation of this review

No browser automation was available in this environment, so the UI-facing fixes (aria-live
placement, focus management, `controlStates` wired into `render()`) were verified by code inspection
and the unit-level `controlStates` tests, **not** by driving the actual page in a browser. A manual
check of Start/Pause/Reset keyboard behavior and screen-reader announcements in a real browser is
recommended before or shortly after shipping, per spec §6 NFR's own manual-check precedent for the
drift NFR.
